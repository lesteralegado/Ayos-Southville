# 06: Run and evaluate the controlled pilot

**Parent:** ../spec.md

**What to build:** Support the owner in running the approved four-week trial and publishing actual consented usability findings and limitations without inflating adoption or repair claims.

**Blocked by:** 05: Verify operational release readiness; explicit human release approval.

**Status:** ready-for-agent

**Execution:** Human-led recruitment and four-week observations; the agent supports records, analysis and fixes within separately authorized scope. This is not an unattended software task.

- [ ] Obtain the accountable owner's explicit release approval before invitation sending or trial start. Confirm permissions and exact targets for any external actions rather than inferring them from ticket status.
- [ ] The owner personally explains the independent trial to consenting adults before invitations; begin with 10 participants. Record minimal consent evidence without public identity/contact exposure.
- [ ] Record the actual start date, four-week period and weekly review results. Maintain daily 7 p.m. Asia/Manila queue checks and the two-business-day review target; review does not guarantee repairs.
- [ ] Use backup takeover and honest resident delay updates for missed reviews. Pause intake when neither operator is available or privacy/authorization fails; pause invitations for broken workflows or missed reviews without coverage. Resume only after recovery and retesting.
- [ ] Expand toward 25 only after weekly evidence shows dependable coverage and safety. Never infer a formal partnership merely from outside contact.
- [ ] Collect outcomes for at least 10 actual consenting participants using the delivered measurement journey. Report whether the 80% unassisted-submission target was met, alongside comprehension, duplicate discovery and lifecycle completion; retain unsuccessful and assisted attempts.
- [ ] Report test-scenario exercises separately from actual concerns and repairs. A software lifecycle exercise is not a successful real resolution; real concerns stay unresolved where appropriate.
- [ ] Publish a dated case study with actual sample size, observation period, method, findings, failures and limitations. No fabricated adoption, official affiliation, unobserved human checks or inflated denominators.
- [ ] Record the owner's end-of-trial decision to continue, fix, pause or end. Missing results or missed targets must be disclosed, not erased; an explicit operational end is separate from merely reaching four weeks.
- [ ] Keep this ticket and the historical release/evaluation gate incomplete until required real findings exist. Evidence is human-provided or directly verified, never generated to satisfy a checkbox.

## Delivery and verification

Use the owner-approved resident-to-operator-to-resident browser/API journey as the primary test seam, with focused behavior tests at existing access, administration, report lifecycle, notification and measurement boundaries. Test observable, durable outcomes rather than implementation details. Reuse existing modules; perform only scoped prefactoring needed for this slice, not a standalone wide refactor.

For UI changes use Impeccable, established product/design context and task-first operating screens; read craft-floor immediately before UI edits. Deliver English/Filipino first-use, loading, empty, validation, pending, success, permission, offline, retry and unexpected-failure states where applicable. Verify phone/tablet/desktop, keyboard focus, screen-reader semantics/live announcements, zoom, contrast and reduced motion. Perform one batched visual inspection, fix findings together and at most one confirmation round; record evidence. Automated checks do not substitute for human assistive-technology testing.

Append completion evidence and update this effort's map only after this ticket's criteria pass. Never fabricate participant results or treat code completion as release approval. Preserve the historical production-completion tickets. No invitation sending, role changes, production deployment, destructive cleanup or restore is authorized merely by this ticket.
